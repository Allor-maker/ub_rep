# Roadmap и точки интеграции

Плановое окно — 7–20 ноября 2026 года, ориентир 3–4 часа на участника в день.
Даты — рабочая гипотеза; точный дедлайн сдачи нужно подтвердить. При более позднем
старте сохраняйте порядок этапов, сокращая P2, а не проверки бюджета и сохранения.

Приоритеты: **P0** — минимальный сквозной harness; **P1** — обязательная надёжность
для конкурсной сдачи; **P2** — улучшения только при измеренном выигрыше и наличии времени.
P0 без P1 не считается готовым конкурсным решением.

## Как избежать ожидания друг друга

- S0 закрыт Contracts v1. A первым маленьким PR реализует models.py/ports.py,
  B параллельно готовит C02/C03/C08/C09 и внутреннюю логику инструментов. До A1
  B не создаёт второй набор DTO. После него оба используют одни Protocol.
- После A1 A делает ledger/gateway, B — ToolExecutor и stateless Solver.step
  на LLMSession-double. B4 использует готовый AttemptResult со snapshot, не ждёт A5.
  Doubles допустимы только в `tests/`, не вместо реальной конкурсной реализации.
- После B1/B2 и A3/A5 интегрируется общий сценарий. Специализации B3 добавляются
  постепенно, без переработки ядра A4.
- B4 возвращает результаты локальной проверки; A5/A6 отвечают за принятие и публикацию.
- B5 предоставляет независимую оценку для A7; без неё сложная оптимизация откладывается.
