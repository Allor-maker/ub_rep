# Условия и неизвестные параметры соревнования

Основание: прочитанный локальный `Регламент соревнования.md` в родительском
каталоге и задание команды. Это рабочая выжимка, не официальный новый регламент.
Исходные материалы не скопированы; подтверждённые ответы организаторов следует
фиксировать здесь с датой и источником, без регистрационных данных.

## Требования локального регламента

| Область | Требование |
| --- | --- |
| Цель | Максимальная награда на 100 задачах; при равенстве меньше токенов |
| Вход | Каталог задач, известные `reward`; все задачи доступны сразу |
| Бюджет | Общий на отбор, планирование и решение; вход/10 + выход |
| Reasoning | Оплачивается как выход; не учитывать повторно, если уже включён |
| Модели | Четыре Qwen, перечисленные в README; только через прокси |
| Framework | Harness на openJiuwen, версия выбирается командой |
| Вычисления | Без GPU, RAM до 16 ГБ, до 5 сессий, время до часа |
| Сеть | При исполнении только прокси; никаких скачиваний |
| Размеры | Репозиторий <100 МБ без `.git`, образ <4 ГБ, сборка <1000 секунд |
| Запуск | В примере `/app/run_agent.py --tasks-dir /data/tasks` |
| Ключи | `LLM_BASE_URL`, `LLM_API_KEY` от организаторов, секретов в Git нет |
| Сохранение | После каждого решения; явное требование `answer.txt` в каталоге задачи |
| Отбор | Обязательное решение обеих выполнимых задач |
| Оценка | Проверка безопасности, сборка, отбор, затем основной прогон |
| Сдача | GitHub/GitFlic; последний коммит до дедлайна |
| Приватный репозиторий | Доступ жюри `promsoft`, `madrugado` должен быть предоставлен |

В команде контейнер имеет read-only корень, `/tmp` tmpfs 2 ГБ, `HOME=/tmp`,
записываемый каталог задач, отключённые capabilities и лимит 512 процессов.
Работоспособность зависимостей, логов и кэшей нужно проверить именно так.

## Дополнительные сведения из задания команды

Доступ NeuralDeep: 7–20 ноября 2026, до 23:59 МСК последнего дня. Заявлены
60 запросов/минуту, 16 параллельных потоков на аккаунт, не более двух внешних IP.
Эти квоты не отменяют более строгие конкурсные ограничения. Дополнительные ключи
одного аккаунта не создают дополнительную квоту. Ключами участники не обмениваются.

Запрещены обход ограничений и массовый сбор ответов для обучения/калибровки
конкурирующих моделей. Классические методы разрешены регламентом, но допустимость
обучения нашего оценщика на траекториях требует отдельного уточнения.

## Наблюдения по восьми примерам

Четыре метки типов, `task.json` и необязательный `workspace/`. Эталоны находятся
в `expected`; проверки примеров — `exact_int`, `exact_str`, `unittest`.
Все примеры выполнимы. Это не гарантия распределения сложности или перечня форматов
финала. В coding-примерах требуется изменённый исходник, неизменные тесты и `DONE`.

## Вопросы организаторам

| ID | Неизвестное | Влияние / временное решение |
| --- | --- | --- |
| Q1 | Величина и способ передачи бюджета; остаток; списание оборванных запросов; предел полного выхода с reasoning | Без этого нет подтверждённой гарантии бюджета; не выдумывать имя env |
| Q2 | `answer.txt` в корне или в `workspace/`; формат и назначение `OUT`; проверка изменений кода | Изолировать в адаптере публикации; `OUT` назван файлом, но создаётся как каталог и не смонтирован в примере |
| Q3 | 4 CPU в тексте или 8 в команде; что считается сессией | Планировать под 4 CPU; предварительно 2 одновременно исполняемые задачи |
| Q4 | Признак и бюджет отборочного запуска | Политика полного покрытия; не пропускать задачу из-за низкой награды |
| Q5 | Возможности финального прокси: usage, tools, structured output, ограничения reasoning, коды ошибок | Проверить адаптер; не переносить автоматически свойства публичного API |
| Q6 | Хранение траекторий и обучение классического оценщика на их метаданных | До уточнения — ограниченная отладка, без массового сбора для обучения |
| Q7 | Точный дедлайн сдачи, доступ к сети при сборке, исправленная команда сборки | Срок доступа API не считать дедлайном; в примере `docker build` не указан build context |

## Требования к будущим файлам запуска

`Dockerfile` и `run_agent.py` добавлены в A6 для B-minimal; результат и команды —
в [отчёте A6](a6-report.md). Python patch и прямые зависимости зафиксированы,
но Linux lock с hashes и digest base image ещё не подготовлены. Windows-разработка
не заменяет проверку Linux-контейнера, которая остаётся открытой. Сборочные секреты
не включаются в слои; runtime не использует соседние каталоги компьютера разработчика.
