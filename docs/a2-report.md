# A2 — Budget Ledger

Реализация в текущей ветке `feature/a2-budget-ledger`, база `494d16f`.
Общие DTO, `BudgetController` и остальные публичные контракты A1 не менялись.
Модули B, A3–A7 и SDK probe не изменялись. Сетевые вызовы и новые зависимости не требуются.

## Что реализовано

- `budget/ledger.py`: один синхронный BudgetLedger на running event loop, глобальный
  лимит/дедлайн и бюджеты попыток. Вызовы из других loop/threads отвергаются.
- Резерв входа и максимального выхода до dispatch, с одновременным учётом глобального
  и локального остатка и слотов. Методы не содержат await, поэтому конкурентные
  корутины не получают один и тот же остаток. Освобождаются только неотправленные записи.
- Полный lifecycle lease, идемпотентные операции, unknown удерживает резерв,
  late exact заменяет удержание фактическим расходом. Повторы не списывают дважды.
- Расход выше резерва записывается полностью до отказа и halt. Разные exact для
  одного ID останавливают новые вызовы, первая запись сохраняется. Halt/закрытие
  не уничтожают обязательства и не мешают поздней сверке.
- Актуальные immutable snapshot: Units, spent/held/available, вызовы и blocked.
  Суммы вычисляются из lease, без второй книги накопительных счётчиков.
- `budget/config.py`: явное чтение BUDGET, Decimal-конверсия без float и без default units.
  Помощники доступны через `from nsu_budget_agent.budget import ...`.
- `tests/contracts/test_budget_ledger.py`: C04/C05/C06, включая конкурирующие задачи,
  отмену/timeout и поздние записи. `typecheck_budget.py` проверяет структурное
  соответствие реализации Protocol. `tests/unit/test_budget_config.py` проверяет ввод.

## Арифметика и BUDGET

`cost_x10 = prompt_tokens + 10 * completion_tokens`, где completion — полный
оплачиваемый выход, включая reasoning. Ledger использует `UsageRecord.cost_units`;
provider-specific included/separate usage должен заранее нормализовать A3.
Вход 120 и выходной cap 60 резервируют 720 Units. Exact 120/40 списывает 520,
высвобождая 200; unknown не списывает условный ноль и сохраняет 720 удержанными.

`budget_from_env(unit="competition_tokens")` считает `floor(10 * Decimal(BUDGET))`.
`unit="units_x10"` принимает уже целые Units. Пример `BUDGET=100`: 1000 Units
в первом режиме и 100 Units во втором. Выбор режима обязателен; дробные Units во
втором режиме отвергаются. Проверены длинные десятичные числа, низкая precision и
ограничения Emax/Emin Decimal вызывающего кода, малые дроби, ноль,
невалидный/отрицательный/не конечный и отсутствующий ввод.

**Неопределённость Q1 сохраняется.** Contracts v1 не подтверждает конкурсное имя
переменной окружения и её единицы. BUDGET добавлен по явному запросу пользователя
как opt-in вход конфигурации, не как автоматически включённый официальный контракт.
До ответа организаторов вызывающий код должен явно выбрать единицы. По значению
переменной, имени модели и наличию дробной части единицы не угадываются.

## Интерпретации v1 и границы ответственности

Противоречий, требующих изменения публичных интерфейсов, не обнаружено. Есть
несколько недоопределённых деталей, реализованных явно:

- `blocked` указывает невозможность нового LLM-резерва из-за halt, дедлайна или
  остатка менее минимальных 10 Units; для попытки также closed/слоты/общий остаток.
  Детерминированная работа и сохранение ответов этим не запрещены.
- Изменившиеся частичные unknown не являются авторитетной сверкой: сохраняется
  первый unknown и весь резерв. При конфликте exact сохраняется первый exact,
  вызывающий код получает accounting_violation; новый баланс по догадке не создаётся.
- Halt идемпотентен и сохраняет первую причину. Повторные вызовы записи доступны;
  repeat reserve существующего ID — чтение текущего снимка, не право отправить снова.
- Порт open_attempt не получает task_id. Правило одной активной попытки задачи
  должен обеспечить оркестратор; ledger не создаёт скрытое сопоставление по ID.
- Закрытие конвертирует dispatched в uncertain после cleanup вызывающим кодом.
  Ledger не отменяет сеть и сам не узнаёт об asyncio cancellation: будущий A3 обязан
  вызвать release/record_usage в своём finally. Даже забытый dispatched удерживает резерв.
- Ошибки программиста — ContractError; ожидаемый ресурсный отказ — OperationFailed.
  Accounting violation поднимается после сохранения расхода, чтобы его не потерять.

Отдельный интеграционный риск для A3: ledger останавливает новые запросы, когда
общая стоимость exact usage превышает резерв, но не сравнивает отдельно полный
оплачиваемый выход с `output_cap_tokens`. Например, при input bound 490 и cap 1
резерв составляет 500 Units; usage с input 0 и output 40 стоит 400 Units, хотя
output cap превышен. A3 должен выявлять такое нарушение подтверждённой границы
даже при стоимости внутри резерва, корректно учитывать расход и прекращать новые
LLM-вызовы по согласованной политике. Эта проверка в A2 не реализована.

## Проверки

Из корня репозитория, PowerShell, Python 3.11:

```powershell
$env:PYTHONPATH = 'src'
python -S -m unittest discover -s tests -v
.\.venv-a1\Scripts\python.exe -m ruff check src tests
.\.venv-a1\Scripts\python.exe -m ruff format --check src tests
$env:MYPYPATH = 'src'
.\.venv-a1\Scripts\python.exe -m mypy src/nsu_budget_agent/contracts src/nsu_budget_agent/budget tests/contracts/typecheck_consumers.py tests/contracts/typecheck_budget.py
```

Результат: **55 тестов успешно** (27 A1 + 24 ledger + 4 конфигурация), Ruff lint/format
и Mypy успешны. Stdlib-тесты выполняются с `-S`; NeuralDeep/SDK и ключи не используются.
Mypy проверяет новый модуль и совместимость BudgetLedger с Protocol, а также прежний
пример потребителей B. Публичные контракты A1 не менялись.

Проверены глобальная/локальная гонка резервов, гонка за слотом, повтор reserve
одного ID, 20 конкурентных доставок usage, нулевой расход со списанным слотом,
точная граница и десятая единицы, отказ без изменения баланса, неверные переходы,
отмена до/после dispatch, timeout с uncertain и late exact после close, halt,
overrun с общим перерасходом и без него, чужие ID/модель и недопустимые входы.

Это локальные проверки на Windows/Python 3.11. Linux/контейнер для A2 не запускался;
workflow `.github/workflows/a1-ci.yml` расширен для всех тестов A1/A2 и Mypy A2,
но результат на Linux будет известен только после успешного GitHub Actions.
Семантика proxy usage, фактические caps и BUDGET не подтверждены. Перерасход провайдера
выше резерва невозможно предотвратить задним числом — он обнаруживается, полностью
учитывается, и новые вызовы прекращаются. Локальная публикация ответов остаётся A5.
Операции линейны по числу lease; история хранится в памяти до завершения процесса.
Commit, push и merge в рамках A2 не выполнялись.
