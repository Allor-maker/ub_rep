# Принятые решения — Contracts v1

7 ноября 2026. Технический этап S0 завершён архитектором в
[Contracts v1](contracts.md). Документ обязателен для обоих участников; повторное
согласование полей/типов перед реализацией не требуется. Общие определения и C01
реализованы в A1; SDK smoke успешен на Windows, Linux ещё не проверен.
Подробности — [отчёт A1](a1-report.md).

## Решения архитектора

| Решение | Причина / следствие |
| --- | --- |
| Python 3.11, stdlib dataclass frozen/slots/kw_only и Protocol | Малый общий слой без новой зависимости; A переносит спецификацию в models.py/ports.py |
| SDK-цель openJiuwen 0.1.19, собственный JiuwenAdapter | Изолирует непроверенный API framework; B работает независимо от него |
| Один asyncio event loop, синхронная книга бюджета | Атомарное резервирование без распределённого состояния и копий баланса |
| Расход в целых десятых; unknown удерживает полный резерв | Нет потерь на округлении и ложного бесплатного timeout |
| Один физический запрос на complete, один complete на шаг | Нет скрытых retry и независимых циклов, расход объясним |
| Текстовый chat и локальный JSON действий | V1 не зависит от native tools/JSON-mode конкретного прокси |
| Решатель возвращает один шаг; цикл и AttemptResult принадлежат A | Устраняет дублирование orchestration и generic solver |
| type_hint открыт; assess чистый; generic обязателен | Новые типы не требуют нового enum или изменения ядра |
| Staging каждой попытки, protected-тесты, отдельный внешний evaluator | Ошибочная попытка не изменяет исходные данные и эталоны не входят в контекст |
| Проверенный execution backend либо unavailable для произвольного кода | Не выдаёт cwd/subprocess за файловую и сетевую изоляцию |
| Accept при отсутствии failed и passed всех blocking-проверок | Позволяет отвечать без локального оракула, не скрывая неопределённость |
| Исходники до answer.txt; первая публикация окончательная | Сохраняет ранее сданные ответы; нет ложного обещания многофайловой атомарности |
| 2 активные задачи по умолчанию, auto coverage для набора из двух | Консервативный старт, отбор не теряет задачу из-за низкой награды |

Первый интеграционный сценарий выбран в разделе 10 contracts.md: незнакомая метка,
файл с новым именем, чтение и строковый ответ, double LLM и реальный JiuwenAdapter.

## Реализационные проверки, а не открытые контракты

- A1 перенёс DTO/Protocol без новой архитектуры; проверка SDK 0.1.19 в Linux открыта.
- A3 реализует ProviderProfile и подтверждает его параметры на доступном прокси.
  Strict по умолчанию не отправляет запрос при непроверенных границах расхода.
- B1 реализует инструменты и проверяемую изоляцию для исполнения кода; A6 проверяет
  совместимость с контейнером. При отсутствии backend инструмент недоступен.
- A6 фиксирует точные транзитивные зависимости/образ и проверяет сборку; эти
  технические результаты не меняют порты B. Финальная сборка пока не проверена.
- Каждый участник читает свою обновлённую инструкцию и берёт задачу по владельцу.

## Только внешние вопросы

| Вопрос | Изолированная точка |
| --- | --- |
| Q1: источник бюджета, полный usage, списание оборванных запросов | RunConfig, ProviderProfile и шлюз; не внутренние единицы ledger |
| Q2: answer.txt, OUT, место проверки кода | SubmissionLayout/Publisher; default проекта — task_root/answer.txt, UTF-8 без добавленной новой строки |
| Q3: CPU 4/8, определение сессии и возможности окружения | Профиль ресурсов/инструментов; до ответа 4 CPU, до 5 сессий, default 2 |
| Q4: признак и бюджет отбора | RunConfig.mode; auto/coverage/portfolio уже определены |
| Q5: доступные функции и ошибки финального прокси | ProviderProfile; native tools не обязательны для v1 |
| Q6: допустимые траектории и обучение оценщика | Только процесс экспериментов/P2 |
| Q7: дедлайн и среда сборки | Процесс сдачи и Docker-проверки |

Точная формулировка — в [competition.md](competition.md). Эти неизвестные не
подменяются правилами, придуманными командой. Владельца GitHub, участников на роли
и лицензию выбирает команда как организационные решения; к интерфейсам это не относится.

## Изменение v1

Зафиксировать проблему, конкретное изменение поля/порта, совместимость и проверки;
обновить contracts.md и затронутые задания одним PR с review второго участника.
Добавление решателя/читателя по существующему порту не требует новой версии контракта.
Ответ организаторов с датой/источником фиксируется отдельно, без ключей и регистраций.
