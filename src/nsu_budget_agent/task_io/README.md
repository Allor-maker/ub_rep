# Вход задач — A

`DirectoryTaskLoader.load(tasks_dir)` обнаруживает непосредственные каталоги задач,
изолирует ошибки в LoadIssue и исключает **все** задачи с дублирующимся ID.
Некорректный корень приводит к OperationFailed. Имена сортируются для воспроизводимости.
Точку входа `--tasks-dir` подключит A6; здесь реализован только порт загрузки.

`OrganizerTaskAdapter.load_task(task_root)` читает UTF-8 `task.json`: обязательны
`task_id`, `instruction`, целочисленный `reward >= 0`; необязательны `task_type` и `check`.
`type` поддерживается как альтернативное публичное имя `task_type`; конфликт диагностируется.
Подтверждены math/search/data_analysis/coding; отсутствующие и новые метки также допустимы.
Синтаксический разбор JSON неизбежно читает байты манифеста, но значение `expected`
не извлекается, не используется и не сохраняется в DTO. Произвольные поля не переносятся.

Рабочий корень — обычный `workspace/`, если он есть, иначе каталог задачи.
Обычный файл с именем workspace не меняет корень. Артефакты содержат относительный
POSIX-путь, размер и SHA-256; содержимое в DTO/промпт не загружается. Неизвестный media_type — None.
Исключаются task.json, answer.txt, expected/expected.*/expected_*, скрытые и известные
служебные области на любом уровне. Эти области не открываются и не обходятся.
Тесты test_*, *_test.py, каталоги test/tests, Python-файлы явных команд pytest/unittest
и вызываемые Python-скрипты test_*/verify_* помечаются protected. Начальный `./`
в команде удаляется перед проверкой оставшегося относительного пути; `python3 main.py` сам по себе
не делает исходник защищённым.
Это консервативное распознавание, не анализ произвольного естественного языка;
другие выбранные тесты обязан дополнительно защитить инструмент B1 до исполнения.

I/O выполняется через asyncio.to_thread и только читает вход. На POSIX обход закреплён
за directory fd с O_NOFOLLOW; на Windows каталоги удерживаются без FILE_SHARE_DELETE,
а конечные handles открываются с FILE_FLAG_OPEN_REPARSE_POINT. Ссылки, reparse points,
hard links, специальные файлы и небезопасные имена отвергаются. Идентичность каталога
из stat сравнивается с открытым handle, включая workspace и данные discovery; для файлов
сравниваются идентичность, размер и времена изменения. Отсутствие file ID — отказ.
У альтернативного доверенного адаптера каждый компонент work_root повторно открывается
внутри task_root без ссылок; `..`, внешние и служебные пути отвергаются.
Недоступный безопасный backend/каталог приводит к отказу, а не к обычному path.open.

Локальные, настраиваемые пределы адаптера: manifest 1 MiB, суммарные артефакты 256 MiB,
10 000 записей и глубина 64; discovery ограничен 10 000 записями корня. Это защитные
пределы реализации, не сведения о формате финала. Отмена await не останавливает поток,
но поток выполняет ограниченное чтение без записи и закрывает handles в finally.
Staging, повторная проверка путей/хешей при копировании и публикация относятся к A5.
Проверки не являются абсолютной защитой от произвольной конкурентной модификации ФС:
объекты могут измениться до первого stat или после возврата DTO, а file ID могут
переиспользоваться. Адаптер выбирается доверенным кодом и сам не ограничивается
песочницей; загрузчик не является ОС-песочницей для произвольного кода.
